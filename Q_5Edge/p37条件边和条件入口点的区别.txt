""" 区别"""
"""
条件边（Conditional Edge）和条件入口点（Conditional Entry Point）的区别。
虽然它们在代码实现上使用的是同一个函数 add_conditional_edges()，但它们在触发时机、源节点（起点）以及业务场景上有着本质的不同。以下是基于你代码的详细对比分析：
1. 触发时机与源节点的区别
  条件边（案例一：奇偶数判断）
      触发时机：在工作流执行到中途时触发。
      源节点：代码中写的是 builder.add_conditional_edges("check_x", ...)。它的起点是普通的业务节点（check_x）。这意味着，必须先执行完 check_x 节点，图引擎才会调用 is_even 函数来决定下一步去哪。
  条件入口点（案例二：问候语路由）
      触发时机：在用户输入到达、工作流刚刚启动的瞬间触发。
      源节点：代码中写的是 stateGraph.add_conditional_edges(START, ...)。它的起点是虚拟的 START 节点。这意味着，图引擎在运行任何业务节点之前，就会先调用 route_input 函数，决定整个流程的“第一站”是哪里。
2. 核心作用与业务场景的区别
  条件边 = “中途的岔路口”
      作用：处理节点执行完毕后的动态流转。
      场景：在案例一中，check_x 节点只负责接收数据，至于接下来是去 handle_even 还是 handle_odd，取决于 is_even 的判断结果。这就像是你在游乐园玩完一个项目后，根据当前的排队人数决定下一个去玩什么。
  条件入口点 = “大门口的分流闸机”
      作用：处理工作流的初始路由分发。
      场景：在案例二中，用户刚输入一句话（比如 "Hello"），系统还没来得及做任何处理，就直接根据 route_input 的返回值，把任务精准地派发给 greeting_node。这就像是游乐园大门口的检票员，根据你的门票类型（VIP或普通），直接指引你去不同的专属通道。
"""
"""
⭐⭐⭐
对比维度	                p32：条件边	                                 p36：条件入口点
API 调用	    add_conditional_edges("check_x", ...)	       add_conditional_edges(START, ...)
第一个参数	       具体的业务节点名称（字符串）	                    固定的 START 常量
路由函数	             is_even (判断奇偶)	                   route_input (判断文本意图)
执行顺序	  START ➡️ check_x ➡️ 条件判断 ➡️ 分支节点	       START ➡️ 条件判断 ➡️ 分支节点 ➡️ END
"""
